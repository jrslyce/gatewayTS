Getting started

Before you start

For the local walkthrough you need Git, Node.js 24, npm, and a browser. For viewer testing, use a broadcaster account, a separate viewer session, and an HTTPS game origin accepted by GameLink. The sample starts with the shared Game ID gamelink-testing. Register your own permanent ID in the developer portal before shipping.

Step 01

Install the SDK

Clone the source and check out the revision used to build this walkthrough. Run the following in a terminal.

git clone https://github.com/jrslyce/hypeline-html5.git
cd hypeline-html5
git checkout 5390aa627152ea836b9633927b2219db02724443
npm ci
npm run build
npm run dev:tutorial

Open the local URL printed by Vite. To add the SDK to a separate game, run npm pack in this checkout and install the resulting tarball in your game. The package still uses the name muxy-gateway-html5. For a plain script tag, download the browser bundle and use HypelineHTML5.HypelineClient.

Checkpoint The demo opens at 50 health and the sign-in panel is visible.

Step 02

Set up the game

Open the vanilla sample. One client owns the game session. Mount the auth form outside the game canvas so the broadcaster can enter a code. Keep the viewer alert inside the area captured on stream.

import { HypelineClient, createAuthWidget } from "muxy-gateway-html5";

const game = new HypelineClient({
  gameId: "gamelink-testing",
  rememberSession: false
});
createAuthWidget(document.querySelector("#gateway-ui"), game);

In TypeScript, check the element exists or use document.querySelector<HTMLElement>("#gateway-ui")! when the host is guaranteed by your markup.

Checkpoint One active client and one auth form serve the game.

Step 03

Configure the healthpack

In the successful authentication callback, publish the game name, a Health text, and the action below. The full action list sets initial inventory, so publish it when initializing the catalog. Use setGameTexts() for subsequent health updates.

Action ID
healthpack
Viewer label
Spawn Healthpack
Category / state
Help / Available
Impact / stock
1 / 3 uses

In onGameActionUsed, show the viewer name and action, then apply up to 10 health. Await acceptGameAction(used, "Restored health") after the effect succeeds. If health is already full, use refundGameAction(). The sample shows a distinct status for acknowledgment and for publishing Health.

Checkpoint One handler shows the alert, applies the effect, and reports the outcome.

Step 04

Test locally

  1. Open the healthpack demo. Select Add 10 health locally and watch health change to 60.
  2. Select Preview alert. The card names “Preview viewer” and “Spawn Healthpack” and clears after six seconds.
  3. Select Reset local demo to return to 50 before connecting.

Checkpoint Both local controls work with no Twitch account. Transaction delivery is verified in step 06.

Step 05

Connect your Twitch channel

  1. Install and activate the Muxy Gateway extension on the broadcaster’s channel. In its configuration, allow your Game ID if it appears under Linked Games.
  2. Request a fresh six-character code. Enter it in the game’s Hypeline panel and select Authenticate. Codes expire after five minutes.
  3. Wait for Ready for viewer actions. in the game. Check that the extension displays Hypeline Healthpack, the Health text, and Spawn Healthpack.

Checkpoint The viewer can see the action and Health 50. Keep codes and tokens out of shared logs and screenshots.

Step 06

Verify a viewer action

Set the action’s price to zero on your own channel for the test. From a separate viewer session, select Spawn Healthpack once. Watch the game directly first, then check the broadcast after its stream delay.

  1. The game shows the viewer’s name and the action. Health increases once, from 50 to 60.
  2. The game shows Action acknowledged. Health published. after both server responses.
  3. The extension shows Health 60 and two remaining uses. Updating text preserves the consumed stock.

Checkpoint Record delivery, alert, gameplay effect, acknowledgment, and extension state separately. If an acknowledgment times out, reconcile the transaction before retrying.

Step 07

Adapt it for your game

Replace the sample health counter with your game’s effect. Disable actions while loading or paused. On unlink, clear the game state while authenticated, then deauthenticate in a finally block. Destroy the widgets and call dispose() when tearing down the game.

Test a fresh code, an invalid code, a reconnect, and a reload of your deployed game. Existing projects can retain GatewayClient and MuxyGatewayHTML5. The wire protocol, extension identifier, and production session keys retain their Gateway names.

Checkpoint One real viewer action still produces one effect and a visible alert on the HTTPS origin you intend to ship.

Help & reference

Troubleshooting

The browser cannot connect

Check that the game uses production and a remote wss:// endpoint. Confirm that GameLink accepts the deployed origin. A local preview verifies only the interface.

The code works but the action is missing

Confirm the Game ID and broadcaster, verify the extension is active, and wait for game setup to finish. Check the action’s published state, remaining stock, and viewer placement.

Health changes but the alert or acknowledgment is missing

Check that the alert is inside the captured game view, and that one handler applies the effect. Inspect the game’s acknowledgment status. Record any uncertain result before making another purchase.
